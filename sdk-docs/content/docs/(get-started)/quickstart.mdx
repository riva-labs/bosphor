This tutorial takes you from an empty project to a file stored on Walrus, with a
proof verified back on your origin chain. It runs against the **hosted Bosphor
testnet**, so there is nothing to deploy: pick EVM (Ethereum Sepolia) or Solana
(devnet) in the tabs below and follow along.

By the end you will have called `storePriced()` once and read back a verified
`{ intentId, blobId, endEpoch, txHash }`.

## Before you start

You need:

- **Node.js 22+** (the SDK is ESM-only).
- A wallet on your origin chain, funded as below.
- An **RPC URL** for that chain. Public endpoints work for a first try.

Every address, endpoint id, and URL ships in the SDK as the `TESTNET` preset, so
you never copy them by hand. They are also listed on the
[Testnet reference](/docs/reference/testnet).

### Fund your wallet

At current testnet prices, a paid store of a 1 KB file for 5 epochs costs about:

| Origin | Cost per store | Faucet | Suggested balance |
|--------|----------------|--------|-------------------|
| Ethereum Sepolia | ~0.0015 ETH plus gas | [Alchemy](https://www.alchemy.com/faucets/ethereum-sepolia), [Google Cloud](https://cloud.google.com/application/web3/faucet/ethereum/sepolia) | 0.02 ETH |
| Solana devnet | ~0.03 SOL incl. account rent | [faucet.solana.com](https://faucet.solana.com) or `solana airdrop 1 --url devnet` | 0.5 SOL |

The price follows live token prices. Check it any time:

```bash
curl -s -X POST https://api.bosphor.xyz/testnet/quote \
  -H 'content-type: application/json' \
  -d '{"sizeBytes":1024,"epochs":5,"originToken":"ETH"}'
```

<Tab value="EVM">

</Tab>

<Tab value="Solana">
```bash
npm install @bosphor/sdk @solana/web3.js @mysten/walrus @mysten/sui @layerzerolabs/lz-solana-sdk-v2
```

`@layerzerolabs/lz-solana-sdk-v2` is optional; with it, quotes include the exact
live LayerZero fee instead of a fee cap.
</Tab>

</Tabs>

`@bosphor/sdk` is the only hard dependency. `ethers` or `@solana/web3.js` signs the
intent, and the `@mysten/*` pair computes the Walrus blob id locally (no network
call, no SUI or WAL needed).

## 2. Create the client

<Tabs groupId="chain" persist items={['EVM', 'Solana']}>

<Tab value="EVM">
```ts title="client.ts"
import { ethers } from 'ethers';
import { createBosphorClientFromSigner } from '@bosphor/sdk/evm';

const provider = new ethers.JsonRpcProvider(process.env.SEPOLIA_RPC_URL);
const signer = new ethers.Wallet(process.env.PRIVATE_KEY!, provider);

// TESTNET preset: adapter address + ABI, relayer URL, Sui EID, LayerZero options.
export const client = await createBosphorClientFromSigner(signer);
```

Any `ethers` v6 signer works, including a browser wallet
(`await new ethers.BrowserProvider(window.ethereum).getSigner()`).
</Tab>

<Tab value="Solana">
```ts title="client.ts"
import { readFileSync } from 'node:fs';
import { Connection, Keypair } from '@solana/web3.js';
import { TESTNET, createBosphorSolanaClientFromKeypair } from '@bosphor/sdk/solana';

const connection = new Connection(process.env.SOLANA_RPC_URL ?? TESTNET.solana.rpcUrl, 'confirmed');
const secret = JSON.parse(readFileSync(process.env.KEYPAIR!, 'utf8')) as number[];
const wallet = Keypair.fromSecretKey(Uint8Array.from(secret));

// TESTNET preset: program id, LayerZero send accounts, fee cap, relayer URL.
export const client = await createBosphorSolanaClientFromKeypair({ connection, wallet });
```
</Tab>

</Tabs>

<Callout type="info" title="The SDK never sees your private key">
It works through your signer or keypair object, so browser wallets and your own
key management work unchanged.
</Callout>

## 3. Preview the price

```ts
const fileBytes = new TextEncoder().encode('hello, permanence');

const encoded = await client.encode(fileBytes, { epochs: 5 });
const quote = await client.priceQuote(encoded);

console.log(quote.totalNative);        // wei (EVM) or lamports (Solana)
console.log(quote.breakdown.totalUsd); // the same amount in USD
```

No wallet yet? `quoteEvmStore` / `quoteSolanaStore` return the same quote from a
read-only provider or connection. See [Pay for storage](/docs/pay-for-storage#quote-without-a-wallet).

## 4. Store in one call

```ts
const { intentId, blobId, endEpoch, txHash, quote: paid } = await client.storePriced(fileBytes, {
  epochs: 5,
  // Optional: fires after each step, e.g. to show the tx link right after signing.
  onProgress: (e) => console.log(e.step, e.step === 'submitted' ? e.txHash : ''),
});

console.log({ intentId, blobId, endEpoch, txHash, paid: paid.totalNative });
```

`storePriced()` runs the whole path and only resolves once every step is verified
against on-chain state:

<Mermaid
  chart={`flowchart LR
    A(encode) --> B(priceQuote) --> C(submitPaid) --> D(upload) --> E(awaitProof)
    C -. wallet signs .-> C
    E -. verified on-chain .-> E`}
/>

- **encode** derives the Walrus blob id locally from the bytes.
- **priceQuote** gets one all-in price from the relayer (storage plus the LayerZero fee).
- **submitPaid** sends the intent and the payment; the storage part is held in escrow.
- **upload** hands the raw bytes to the relayer out-of-band.
- **awaitProof** polls until the return proof lands, which also releases the escrow.

A round trip normally completes in one to three minutes. See
[Pay for storage](/docs/pay-for-storage) for the escrow and refund model.

<Callout type="info" title="Free stores on testnet">
`client.store(bytes, { epochs })` runs the same flow paying only the LayerZero fee.
The hosted testnet relayer accepts these today, which is handy for experiments.
Build against `storePriced()`: it is the path paid storage uses.
</Callout>

## 6. Handle the two failure modes

Nothing is fabricated on error. The two you will actually hit:

```ts
import { ProofTimeoutError, RelayerUploadError } from '@bosphor/sdk';

try {
  await client.storePriced(fileBytes, { epochs: 5 });
} catch (e) {
  if (e instanceof RelayerUploadError) {
    // The relayer rejected the upload: e.status, e.reason, e.intentId.
  } else if (e instanceof ProofTimeoutError) {
    // Not executed yet, but the intent is on-chain: re-poll awaitProof(e.intentId).
  } else {
    throw e;
  }
}
```

See [Handle errors](/docs/errors) for the full model.

<Callout type="warn" title="A timeout is not a loss">
`ProofTimeoutError` means the proof had not landed yet, not that the intent
failed. The intent and your escrow are on-chain and the bytes are with the
relayer, so re-poll `awaitProof(intentId)`. See [Resume after a crash](/docs/resume).
</Callout>
