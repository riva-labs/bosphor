title: Store from EVM
description: Submit a storage intent from an EVM wallet and drive the flow step by step.
---

The EVM client wraps the Bosphor adapter contract bound to your `ethers` signer.
The one-call path is in the [Quickstart](/docs/quickstart); this guide covers the
pieces you reach for when you need more control.

## One call

```ts
import { createBosphorClientFromSigner } from '@bosphor/sdk/evm';

const client = await createBosphorClientFromSigner(signer); // hosted testnet

const { intentId, blobId, endEpoch, txHash } = await client.storePriced(fileBytes, { epochs: 5 });
```

`createBosphorClientFromSigner` binds the adapter with the SDK's bundled
`ADAPTER_ABI`, wires the `queryProof` reader used to resolve `endEpoch`, and fills
the adapter address, relayer URL, Sui endpoint id, and LayerZero options from the
`TESTNET` preset. Override any of them in the second argument, for example
`{ network: myPreset }` or `{ relayerUrl }`. See [Pay for storage](/docs/pay-for-storage)
for what `storePriced()` charges.

## Wire it by hand

For a custom deployment or your own `ethers` setup, build the pieces yourself:

```ts
import { ethers } from 'ethers';
import { ADAPTER_ABI, TESTNET, createBosphorClient, fromEthersContract } from '@bosphor/sdk/evm';

const contract = new ethers.Contract(TESTNET.evm.adapterAddress, ADAPTER_ABI, signer);

const client = createBosphorClient({
  adapter: fromEthersContract(contract),
  relayerUrl: TESTNET.relayerUrl,
  dstEid: TESTNET.sui.eid,
  options: TESTNET.evm.lzOptions, // required: the adapter rejects empty options
});
```

`fromEthersContract(contract)` builds the full adapter surface from an
`ethers.Contract` (including the `queryProof` reader), so you never cast with
`as unknown as AdapterContract` or hand-write proof-log parsing.

## Drive the steps yourself

Every step `storePriced()` orchestrates is public, so you can split signing across
separate user interactions (for wallet popups) or persist between steps:

```ts
const encoded = await client.encode(fileBytes, { epochs: 5 });
const quote = await client.priceQuote(encoded);
const { intentId, txHash } = await client.submitPaid(encoded, quote); // wallet signs here
await client.upload(intentId, fileBytes);
const { blobId, endEpoch } = await client.awaitProof(intentId, {
  timeoutMs: 300_000,
  pollMs: 3_000,
});
```

For the free testnet path, `quote(encoded)` and `submit(encoded, fee)` replace
`priceQuote` and `submitPaid`.

Splitting `submitPaid` from later steps matters in the browser: a wallet popup must
open in direct response to a user gesture, so each signature belongs in its own
event handler.

## Progress and refunds

`store()` and `storePriced()` accept `onProgress`, called after each step:

```ts
await client.storePriced(fileBytes, {
  onProgress: (e) => {
    // e.step: 'encoded' | 'quoted' | 'submitted' | 'uploaded' | 'proven'
    if (e.step === 'submitted') console.log('tx', e.txHash);
  },
});
```

If no proof lands before the deadline, `client.refund(intentId)` credits the
escrow back to the payer and `client.withdraw()` pays it out; `client.getEscrow(intentId)`
reads its status. See [Pay for storage](/docs/pay-for-storage#refund-an-escrow).

## Blob-id computation

The Walrus blob id is derived locally from the bytes, so the id the SDK commits to
on-chain matches what the relayer recomputes on ingest. The default lazily loads
`@mysten/walrus`. Because the RedStuff encoding depends on the network, the blob id
differs between testnet and mainnet.

For **mainnet**, set `network: 'mainnet'` on the client (the default is
`'testnet'`), or inject your own `computeBlob` to avoid the Walrus dependency:

```ts
// Simplest: let the SDK build the mainnet-bound default.
const client = createBosphorClient({ adapter, relayerUrl, dstEid, network: 'mainnet' });

// Or inject your own (must return the same id the relayer computes for the bytes).
const custom = createBosphorClient({
  adapter,
  relayerUrl,
  dstEid,
  computeBlob: async (data) => ({ blobId, size: data.length, encodingType: 0 }),
});
```

The injected function must return the same id the relayer computes for the same
bytes, or the on-chain reference check rejects the intent.

## Cancellation

Pass an `AbortSignal` to cancel the wait and the in-flight upload:

```ts
const ac = new AbortController();
setTimeout(() => ac.abort(new Error('took too long')), 30_000);
await client.store(fileBytes, { epochs: 5, signal: ac.signal });
```

The on-chain intent is not rolled back. See [Resume after a crash](/docs/resume).

Runnable end-to-end scripts live at `sdk/examples/store-file-priced.evm.ts` and
`sdk/examples/store-file.evm.ts`.
