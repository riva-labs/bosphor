TypeScript SDK for building on Bosphor. Store a file on Walrus from an EVM or
Solana wallet, over LayerZero, and get a verifiable proof back on the origin
chain. One package, one call.

## Installation

The SDK ships as ESM. Install it alongside the peer packages for the chain you
target. Chain SDKs are optional peer dependencies, loaded lazily, so a
codec-only or single-chain consumer never pulls the ones it does not use.

```bash
# EVM path
npm install @bosphor/sdk ethers @mysten/walrus @mysten/sui

# Solana path
npm install @bosphor/sdk @solana/web3.js @mysten/walrus @mysten/sui
```

## Quick start

Point the client at the relayer and a wallet, then call `store`. The whole
cross-chain flow runs in one call and returns a result verified against
on-chain state.

```ts
const result = await client.store(bytes, { epochs: 5 });
// { intentId, blobId, endEpoch }
```

The [Quickstart](/docs/quickstart) takes you from install to a verified
round-trip.

## Why the SDK

<Cards>
  <Card title="One call" href="/docs/quickstart">
    `await client.store(bytes, { epochs })` runs the whole cross-chain flow and
    returns `{ intentId, blobId, endEpoch }`, verified against on-chain state.
  </Card>
  <Card title="Flat cross-chain cost" href="/docs/how-it-works">
    The blob id is committed on-chain and the bytes travel out-of-band, so the
    LayerZero fee is the same for a 1 KB file and a 1 GB file.
  </Card>
  <Card title="Same API on every chain" href="/docs/solana">
    The EVM and Solana clients are identical where they overlap; the intent id is
    the same keccak digest across EVM, Sui, and Solana.
  </Card>
  <Card title="Lean by default" href="/docs/evm">
    Chain SDKs are optional peer dependencies loaded lazily, so a codec-only or
    single-chain consumer never pulls them.
  </Card>
</Cards>
