---
title: Store from Solana
description: Submit a storage intent from a Solana wallet with the same one-line API.
---

The Solana path has the **same one-line API** as EVM. The only shape difference:
Solana has no separate on-chain `quote` step, so the LayerZero fee is passed as a
`nativeFee` cap (lamports) on the submit instruction.

```
encode -> priceQuote -> submitPaid -> upload -> awaitProof
```

## One call

```ts
import { Connection, Keypair } from '@solana/web3.js';
import { TESTNET, createBosphorSolanaClientFromKeypair } from '@bosphor/sdk/solana';

const connection = new Connection(TESTNET.solana.rpcUrl, 'confirmed');
const client = await createBosphorSolanaClientFromKeypair({ connection, wallet: keypair });

const { intentId, blobId, endEpoch, txHash } = await client.storePriced(fileBytes, { epochs: 5 });
```

The helper fills everything from the `TESTNET` preset: the program id, the
LayerZero send accounts, the LayerZero options, a `nativeFee` cap of 0.01 SOL
(the endpoint charges only the live fee), a live LayerZero fee quote for
`priceQuote()`, a 400k compute-unit limit for the endpoint call, the Sui endpoint
id, and the relayer URL. Override any of them in the options. See
[Pay for storage](/docs/guides/pay-for-storage) for what `storePriced()` charges;
the free testnet path is `client.store(bytes, { epochs })`.

### The live LayerZero fee

`priceQuote()` and `quoteSolanaStore()` price the forward leg at the live
LayerZero fee, read by simulating the endpoint's `quote` instruction (nothing is
sent). Where the simulation runs depends on what you installed:

| Setup | Fee source | `forwardIsUpperBound` |
|-------|-----------|-----------------------|
| `@layerzerolabs/lz-solana-sdk-v2` installed (scripts, servers) | Simulated locally with `quoteSolanaLzFee` | `false` |
| No LayerZero SDK, for example a browser (SDK 0.14.0+) | The relayer runs the same simulation: `GET /lz-fee/solana`, `fetchSolanaLzFee()` | `false` |
| A relayer without that endpoint | The preset cap (0.01 SOL) | `true`: the real charge is lower |

A failed simulation throws (a `RelayerRequestError` with `retryAfterMs` from the
relayer): the SDK never guesses a fee.

## Sign with a browser wallet

From `@bosphor/sdk` 0.14.0, `wallet` can be a browser wallet instead of a
`Keypair`: anything with `publicKey` and `signTransaction`, as Phantom, Solflare,
Backpack and `@solana/wallet-adapter` expose. The SDK builds each transaction,
the wallet asks the user to approve it, and the SDK sends and confirms it. The
secret key never reaches your code.

```tsx
import * as web3 from '@solana/web3.js';
import { useConnection, useWallet } from '@solana/wallet-adapter-react';
import { createBosphorSolanaClientFromWallet } from '@bosphor/sdk/solana';

export function useBosphor() {
  const { connection } = useConnection();
  const wallet = useWallet(); // { publicKey, signTransaction, ... }

  return async (bytes: Uint8Array) => {
    const client = await createBosphorSolanaClientFromWallet({
      connection,
      wallet,
      web3, // pass the module so your bundler resolves it
      computeBlob: 'relayer', // blob id from the relayer, no Walrus WASM
      appId: 'my-dapp',
    });
    return client.storePriced(bytes, { epochs: 5 });
  };
}
```

Without the wallet adapter, pass Phantom's provider directly
(`wallet: window.phantom.solana` after `connect()`). A disconnected wallet
(`publicKey` is `null`) throws before anything is sent, and a transaction that
fails on-chain throws with its program error. `createBosphorSolanaClientFromWallet`
takes the same options as `createBosphorSolanaClientFromKeypair`; the only
browser-specific ones are `web3` and `computeBlob: 'relayer'`, and the only package
you need next to `@bosphor/sdk` is `@solana/web3.js`.

## Progress and refunds

`store()` and `storePriced()` accept `onProgress` (steps `encoded`, `quoted`,
`submitted` with the signature as `txHash`, `uploaded`, `proven`). If no proof
lands before the deadline, `client.refundEscrow(intentId)` returns the escrow to
the payer; see [Pay for storage](/docs/guides/pay-for-storage#refund-an-escrow).

## LayerZero send accounts

`submit_intent` calls into the LayerZero endpoint, which needs a fixed list of
accounts appended to the instruction. The list depends only on the pathway
(Bosphor on Solana devnet to Sui testnet) and the payer, so the SDK publishes it:

```ts
import { testnetEndpointAccounts } from '@bosphor/sdk/solana';

const endpointAccounts = testnetEndpointAccounts(keypair.publicKey);
```

If LayerZero changes the pathway configuration, the snapshot goes stale. Resolve
the live list on-chain instead (needs the optional peer
`@layerzerolabs/lz-solana-sdk-v2`) and pass it to the helper:

```ts
import { resolveEndpointAccounts } from '@bosphor/sdk/solana';

const endpointAccounts = await resolveEndpointAccounts({ connection, payer: keypair.publicKey });
const client = await createBosphorSolanaClientFromKeypair({ connection, wallet: keypair, endpointAccounts });
```

## Wire it by hand

The helper is a thin layer over `createDefaultSolanaChain` and `BosphorSolanaClient`:

```ts
import {
  BosphorSolanaClient,
  TESTNET,
  createDefaultSolanaChain,
  testnetEndpointAccounts,
} from '@bosphor/sdk/solana';

// Anchor-free: no IDL, no Program.
const chain = await createDefaultSolanaChain({
  connection,
  wallet: keypair,
  programId: TESTNET.solana.programId,
  endpointAccounts: testnetEndpointAccounts(keypair.publicKey),
  computeUnitLimit: TESTNET.solana.computeUnitLimit,
});

const client = new BosphorSolanaClient({
  chain,
  relayerUrl: TESTNET.relayerUrl,
  dstEid: TESTNET.sui.eid,
  options: TESTNET.solana.lzOptions,
  nativeFee: TESTNET.solana.nativeFee,
});
```

The canonical intent id is the **same keccak digest** as the EVM and Sui paths. The
backend derives it from the on-chain nonce and cross-checks it against the
`IntentSubmitted` event in the confirmed transaction.

## The chain seam

`BosphorSolanaClient` talks to the chain through a minimal structural interface,
`SolanaChain` (`submitIntent(fields)` and `readIntent(intentId)`). The default
backend loads `@solana/web3.js` via a lazy dynamic import, so a codec-only or
EVM-only consumer never pulls the Solana stack; in a browser bundle pass the module
as `web3` instead (`createDefaultSolanaChain({ connection, wallet, web3 })`). The
`wallet` there is a `Keypair` or a browser wallet signer, as above. Unit tests
inject a fake `SolanaChain`.

## Reading the proof on-chain

The on-chain proof of record is the `IntentState` PDA (`[b"intent", intentId]`),
which `lz_receive` marks `executed` and stamps with the blob id and end epoch.
For CPI or off-chain readers:

```ts
import { decodeIntentState, readSolanaProof } from '@bosphor/sdk/solana';

const info = await connection.getAccountInfo(intentPda);
const { executed, blobId, endEpoch } = readSolanaProof(info!.data);
```

Runnable end-to-end scripts live at `sdk/examples/store-file-priced.solana.ts` and
`sdk/examples/store-file.solana.ts`.
