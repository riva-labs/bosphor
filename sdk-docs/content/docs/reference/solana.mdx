The Solana client has the same one-line API as EVM and talks to the chain through
a minimal `SolanaChain` seam. See the [Solana guide](/docs/solana) for usage. The
tables below are generated from the SDK source.

## BosphorSolanaClient

Same one-line API as EVM, minus the `quote` step (the LayerZero fee is passed as
`nativeFee` on submit).

### Methods

| Method | Signature | Returns |
|--------|-----------|---------|
| `store` | `store(data: Uint8Array, opts?: EncodeOptions & AwaitProofOptions)` | `Promise<StoreResult>` |
| `encode` | `encode(data: Uint8Array, opts?: EncodeOptions)` | `Promise<EncodedIntent>` |
| `submit` | `submit(encoded: EncodedIntent, opts?: SubmitOptions)` | `Promise<{ intentId: Hex; txHash: string }>` |
| `upload` | `upload(intentId: Hex, data: Uint8Array, opts?: { signal?: AbortSignal })` | `Promise<void>` |
| `awaitProof` | `awaitProof(intentId: Hex, opts?: AwaitProofOptions)` | `Promise<{ blobId: Hex; endEpoch: bigint }>` |

## Functions

- `createBosphorSolanaClient(options)`: factory that mirrors `new BosphorSolanaClient(options)`.
- `createDefaultSolanaChain(options)`: builds the default `SolanaChain` backend (lazily loads `@solana/web3.js`).
- `createDefaultComputeBlob(network)`: build the blob-id computation bound to `"testnet"` or `"mainnet"` (the client also accepts a `network` option).
- `decodeIntentState(data)` / `readSolanaProof(data)`: decode the `IntentState` account bytes.
- `BOSPHOR_PROGRAM_ID`, `INTENT_STATE_LEN`: the program id and account length constants.
